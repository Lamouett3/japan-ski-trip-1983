🎯 Implementation Methods

Method 1: Simple <img> with srcset

Best for: Simple cases, quick implementation

<img src="./images/photo.jpg"
     srcset="./images/optimized/webp/photo_640w.webp 640w,
             ./images/optimized/webp/photo_1024w.webp 1024w,
             ./images/optimized/webp/photo_1440w.webp 1440w"
     sizes="(max-width: 640px) 100vw,
            (max-width: 1024px) 100vw,
            1440px"
     alt="Descriptive text"
     loading="lazy"
     width="1440"
     height="900"
     class="responsive-img">

Method 2: <picture> with WebP Fallback

Best for: Maximum compatibility, optimal format selection

<picture>
    <!-- WebP for modern browsers -->
    <source srcset="./images/optimized/webp/photo_640w.webp 640w,
                    ./images/optimized/webp/photo_1024w.webp 1024w,
                    ./images/optimized/webp/photo_1440w.webp 1440w"
            type="image/webp"
            sizes="(max-width: 640px) 100vw,
                   (max-width: 1024px) 100vw,
                   1440px">
    
    <!-- JPEG fallback for older browsers -->
    <img src="./images/photo.jpg"
         alt="Descriptive text"
         loading="lazy"
         width="1440"
         height="900"
         class="responsive-img">
</picture>
💡 Tip: The sizes attribute tells the browser how much space the image will take. The browser then selects the optimal width from srcset.

Method 3: Using CSS Background Images

Best for: Hero sections, decorative backgrounds

/* CSS */
.hero {
    background-image: url('./images/optimized/webp/hero_1440w.webp');
    background-size: cover;
    background-position: center;
    min-height: 100vh;
}

@supports (background-image: url('data:image/webp;base64,...')) {
    /* WebP supported */
}

@media (max-width: 1024px) {
    .hero {
        background-image: url('./images/optimized/webp/hero_1024w.webp');
    }
}

@media (max-width: 640px) {
    .hero {
        background-image: url('./images/optimized/webp/hero_640w.webp');
    }
}

Device Width Format Quality

⚡ Lazy Loading

Always add loading="lazy" to defer image loading until near the viewport.

This significantly improves initial page load performance.

<img src="./images/photo.jpg"
     alt="Description"
     loading="lazy"
     width="1440"
     height="900">

🔍 Accessibility

  • Always include alt text - describe the image content
  • Set width and height - prevents layout shift
  • Use semantic images - meaningful alt text for content images
  • Decorative images - empty alt="" if purely decorative
<!-- ✅ Good: Descriptive alt text -->
<img src="photo.jpg" 
     alt="Skier descending snowy mountain slope"
     width="1440" height="900">

<!-- ❌ Bad: No alt text or generic -->
<img src="photo.jpg" alt="photo">

📥 Integration Steps

  1. Run optimization script: 
    python3 optimize_images.py
  2. Check output: 
    /images/optimized/
├── webp/          # WebP variants
│   ├── photo_640w.webp
│   ├── photo_1024w.webp
│   └── photo_1440w.webp
├── jpg/           # JPEG fallbacks
│   └── photo.jpg
└── variants.json  # Mapping for easy reference
  3. Update HTML: Use Method 1, 2, or 3 above
  4. Test responsiveness: Use browser DevTools to simulate different devices

WebP Support Check:

// In JavaScript console:
function canUseWebP() {
    const canvas = document.createElement('canvas');
    return canvas.toDataURL('image/webp').indexOf('data:image/webp') === 0;
}
console.log('WebP supported:', canUseWebP());

📈 Performance Metrics

Expected improvements after optimization:

Before (monolithic images):
- Images total: ~8-12 MB
- Initial load: 3-5 seconds (on mobile)
- Largest Contentful Paint (LCP): 2.5-3.5s

After (optimized with PHASE 4):
- Images total: ~2-3 MB
- Initial load: 1-2 seconds (on mobile)
- Largest Contentful Paint (LCP): 0.8-1.5s

Estimated savings: 65-75% reduction in image bandwidth

🔒 Security & Best Practices

  • Always validate image sources - use relative paths only
  • Set appropriate crossorigin attributes if needed
  • Use Content Security Policy to control image sources
  • Compress WebP at quality 85-90% for best balance
  • Include width/height to prevent Cumulative Layout Shift (CLS)
